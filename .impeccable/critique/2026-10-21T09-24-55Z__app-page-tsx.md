### Design Specificity Verdict

- **LLM assessment**: The interface is torn between three competing visual identities: a generic SaaS template (excessive rounded cards, gradient ribbons, decorative icons), an internal developer console (boasting "Dual-Tier Fast-Path", "Cloudflare 300+ Edge POPs", "< 10ms RPC"), and a legacy spreadsheet export (1990s Excel pastel green/pink fills). It lacks the confident, restrained aesthetic expected of an institutional gold trading and executive analytics workstation.
- **Deterministic scan**: `impeccable detect` completed with code 0 across markup files (no automated syntax/contrast token violations detected by the CLI engine). However, manual architectural review uncovered critical business logic flaws: hardcoded scaling multipliers (`HQ = 0.38`, `BCEL = 0.72`) and silent mock fallbacks in API handlers.
- **Visual overlays**: In-browser script injection skipped during static codebase review.

### Overall Impression
The application has impressive infrastructure intentions (sub-10ms response, Cloudflare edge caching, 1.4M row capacity), but the frontend design obscures business reality. It presents too much technical telemetry and visual noise while failing to deliver a clear 5-second answer to executive performance questions.

### What's Working
1. **Clear Domain Division**: The 3-pillar separation into *Platform Overview*, *Buy Activity (Inflow)*, and *Sell Activity (Outflow)* reflects the actual business structure of gold trading operations.
2. **Tabular Numerals**: Numeric metrics consistently leverage `font-mono tabular-nums`, preserving vertical character alignment across cards.
3. **Sub-10ms Fast Path Intent**: The underlying database rollup architecture (`summary_weekly_metrics`) is well-conceived for rapid data access.

### Priority Issues

- **[P0] Silent Synthetic Fallback & False Parity**
  - *Why it matters*: When Supabase RPC queries fail, API handlers silently compute fake metrics using decimal multipliers and return HTTP 200, misleading leadership during high-stakes meetings.
  - *Fix*: Remove mock generators; return HTTP 502/503 with user-facing retry state.
  - *Suggested command*: `/impeccable harden app/api/dashboard`

- **[P0] Conflicting Prorating Math (233% Volume Overstatement)**
  - *Why it matters*: `app/page.tsx` prorates by dividing by elapsed days and multiplying by 7, while `PlatformOverviewSection.tsx`, `BuyActivitySection.tsx`, and `SellActivitySection.tsx` multiply raw figures directly by 7.
  - *Fix*: Unify run-rate calculations into a single immutable utility function (`lib/utils/runRate.ts`).
  - *Suggested command*: `/impeccable clarify lib/utils/runRate.ts`

- **[P1] Micro-Combo Chart Visual Noise in Small KPI Cards**
  - *Why it matters*: Jamming dual bar-and-line charts into tiny 95px cards creates overlapping labels, unreadable bars, and cognitive fatigue.
  - *Fix*: Replace card charts with clean, high-clarity sparklines with min/max indicators; reserve combo charts for the full-width historical section.
  - *Suggested command*: `/impeccable distill components/dashboard/MetricKpiCard.tsx`

- **[P1] Developer Telemetry Overcluttering Executive Header**
  - *Why it matters*: "Edge Active (0ms)" and "Dual-Tier Fast-Path" popovers clutter the primary executive viewport.
  - *Fix*: Relocate technical diagnostics to an Admin modal; keep the header focused on data currency and reporting period.
  - *Suggested command*: `/impeccable quieter app/page.tsx`

- **[P2] Outdated Excel Conditional Formatting in Run-Rate Tables**
  - *Why it matters*: Table cells mimic 1990s Excel fills (`#c6efce` green / `#ffc7ce` red), looking like an unformatted raw spreadsheet export.
  - *Fix*: Modernize with clean neutral backgrounds, subtle borders, and restrained financial delta badges.
  - *Suggested command*: `/impeccable polish components/dashboard/targets/ClassicRunRateTables.tsx`
